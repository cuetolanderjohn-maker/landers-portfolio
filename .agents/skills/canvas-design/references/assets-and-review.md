# Asset direction and visual review

## Plan imagery for its use

Before generating or sourcing, define a compact asset plan. For each necessary asset, identify:

- Role and placement: hero, project illustration, supporting detail, background, texture, or icon.
- Subject and intended meaning.
- Shared style: medium, palette, lighting or marks, level of detail, and surface treatment.
- Composition: focal position, negative space, text exclusion areas, aspect ratio, and mobile crop.
- Format requirements: transparent cutout, full background, or repeatable texture where appropriate.
- Source status: supplied, generated, sourced, or missing.

Plan only assets the layout needs. Do not generate a large set to discover later that none fit.

## Generate a coherent set

When generation is requested and available, use the appropriate tool or image skill. Carry forward the confirmed direction rather than re-interviewing the user about decisions already made.

Start with a representative asset. Inspect its subject, composition, quality, palette, edges, and usability at the intended scale. Use a successful result as a visual reference for subsequent assets when the tool supports it. Keep the medium and treatment consistent while varying subjects and framing to suit their placement.

Put navigation, important labels, and body copy in live interface text instead of baking them into generated imagery. For diagrams or scientific subjects, do not treat plausible generated marks as verified factual detail.

Use bounded, targeted revisions when a result misses its purpose. Revise the specific failing quality rather than regenerating indefinitely. If repeated attempts fail, propose an alternative composition or asset treatment.

Do not fabricate portfolio evidence, testimonials, customer logos, product photographs presented as real products, or personal portraits presented as authentic. Conceptual artwork and clearly identified mockups can support the design without pretending to be evidence.

If image tools are unavailable, provide project-specific image prompts with placement and format requirements. Label assets as pending. Do not substitute broken image URLs or claim generation succeeded.

## Reusable image-prompt pattern

Describe: intended website role; subject; visual medium; consistent style characteristics; composition and negative space; background or transparency; aspect ratio; important exclusions specific to this asset.

Example for a confirmed graphite dragon direction:

"Hero illustration for an illustrator's portfolio: a coiled dragon drawn with broad, directional soft graphite on warm textured paper, fine contour work around the head and heavier shading beneath the body. Place the dragon on the right with a calm, lightly textured area on the left reserved for live heading text. Use the same charcoal values and pencil mark treatment as the supporting illustrations. Landscape composition, with the head retained in a narrow mobile crop. No lettering or interface elements."

This is an example, not a default image prompt. For a transparent cutout, request transparency explicitly and use the generator's transparency setting rather than requesting a painted paper background.

## Review the actual interface

When a preview environment is available, inspect the requested targets. For websites, use wide and narrow browser viewports; for native apps, use the running device/emulator or desktop window. Use screenshots and interaction checks as evidence. Review the whole page or key screen flow, not just the opening, and examine critical forms or states where relevant. If preview tools are unavailable, inspect source and report the visual review as unverified.

For apps, plan assets for actual control sizes, display scaling, themes, and packaged resource loading. Raster generation can supply illustrations or textures; it does not automatically produce a coherent vector icon system or a finished adaptive launcher icon. Use live toolkit controls for actions and labels, and provide suitable assets for requested targets.

### Fit and identity

- Can the intended visitor understand the offering and primary action?
- Is the motif meaningful and appropriately prominent?
- Does the content represent actual supplied work or facts?
- Could the same copy and composition be moved unchanged to an unrelated site? If so, identify what needs to become more specific.

### Composition and visual craft

- Check heading hierarchy, readable body text, line lengths, spacing, and alignment.
- Check image placement, crops, unwanted baked-in text, background seams, and consistency across the set.
- Make section compositions respond to content while preserving a shared visual language.
- Check decorative marks, textures, labels, and overlays for collisions or loss of readability.
- Judge gradients, cards, serif fonts, color, and symmetry by their role; do not use a universal banned-style list.

### Behavior and access

- Verify primary navigation, links, buttons, forms, and genuine integrations within the requested scope.
- Check keyboard access, visible focus, text contrast, and meaningful alternatives for pointer effects.
- Ensure content remains available with reduced motion and on touch devices.
- Keep sound optional and user-controlled. Check interruption and reversal behavior for central animations.
- Check responsive composition, overflow, image loading, and appropriate loading, empty, error, and success states.
- Measure any claimed performance target on an identified environment. Do not infer performance from code or screenshots alone.

### Honest completion

Distinguish implemented functionality from visual approximations and demonstrative data. For example, a local drawing wall is not a persistent shared gallery, and a hover blur is not a physical pigment simulation.

Fix material issues found within scope, then summarize the delivered result and verification limits. Re-review after meaningful changes; avoid repeating checks without new evidence or a reason.
